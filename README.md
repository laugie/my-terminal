# my-terminal

自用的轻量 SSH 客户端（Termius 替代），支持 macOS 和 Windows。基于 Tauri 2 + xterm.js，调用系统自带 ssh，配合 Tailscale SSH 点击即连。

- 版本计划：[docs/PLAN.md](docs/PLAN.md)
- 变更记录：[CHANGELOG.md](CHANGELOG.md)

当前状态：v0.1 骨架（Tauri 2 + Vite + 原生 TypeScript）。本地预览：`npm ci && npm run tauri dev`。开发由 AI 工程团队以草稿 PR 方式进行，合并需仓库所有者授权。

## 登录锁

启动默认进入拓扑首页，不要求登录。顶部工具栏右端的齿轮可以打开设置，里面有「界面缩放」（见下节）和「启动时需要登录」。这个开关默认关闭，写在本机 `config.json` 的 `settings.loginLockEnabled`（没有这个字段的旧配置也视为关闭）。配置版本号不变。

打开开关后，从下次启动起才要求登录，当前这次仍可继续使用。如果还没设过口令，打开开关会马上进入设置：用户名 1 到 64 个字符，区分大小写；口令要输入两次，至少 8 个字符，没有别的复杂度要求。设置成功才把开关写成打开。已经有口令时，打开开关不会再问一次，下次启动用原来的口令登录。

关闭开关立即生效。还没设过口令时可以直接关。已经设过口令时，要先输入用户名和口令；输错计入下面的等待，和登录共用同一次数。关掉开关不会删除凭据库里的哈希。

口令只以 argon2id 哈希（随机 16 字节盐，PHC 字符串）和用户名一起放在系统凭据库的一条记录里，service 名是 `my-terminal`。macOS 在「钥匙串访问」，Windows 在「凭据管理器」。应用不把口令写进配置文件、日志或浏览器的 localStorage。开关打开时，每次启动都要重新登录。用户名或口令不对时，提示都是「用户名或密码错误」。配置文件损坏并被重置时，开关回到关闭，并在设置里提示。配置来自更新版本时只读加载，开关不能改。

连续输错 5 次后需要等待 30 秒才能再试，之后每再错一次，等待时间翻倍，最长 15 分钟。等待没有结束时不能提交，界面显示剩余时间。退出再打开，等待和失败次数还在。把系统时间往回拨，不会让剩余等待变短。

应用里没有「忘记口令」或重置按钮。如果真的忘了：在 macOS「钥匙串访问」或 Windows「凭据管理器」里删掉 service 为 `my-terminal` 的那一条，再打开应用，会重新出现首次设置。这道锁只防旁人打开应用。能操作本机账户的人（包括本机管理员）可以删掉这条凭据、改系统时间，或者调试进程，锁防不住他们。凭据库拒绝访问或条目损坏时，应用不会放行，也不会退回首次设置。

## 界面缩放

界面和终端字体一起放大或缩小，用的是 webview 自带的页面缩放（macOS 为 WKWebView `pageZoom`，需要 macOS 11 及以上；Windows 为 WebView2 `ZoomFactor`）。档位与浏览器相同：50%、67%、75%、80%、90%、100%、110%、125%、150%、175%、200%，到两端不再变化。

- macOS：Cmd+= 放大，Cmd+- 缩小，Cmd+0 恢复 100%。
- Windows：Ctrl+= 放大，Ctrl+- 缩小，Ctrl+0 恢复 100%。

带 Shift 的写法（`+`、`_`）和小键盘的 + / - / 0 也可以。这些键在终端里也由应用处理，不发给远端；在登录框等输入框里同样生效。注意 Windows 上裸 Ctrl+- 原本会把 `^_`（readline 的撤销）发给 shell，现在被缩放占用。设置里的「界面缩放」一行有 −、当前百分比、+ 和「重置」。

每次缩放后，当前终端重新计算行列，并把新的大小告诉远端。其他标签切过去时再计算。

缩放比例写在本机 `config.json` 的 `settings.uiZoom`（整数百分比），重启后保持，登录界面也按这个比例显示。100% 时不写这个字段，所以没缩放过的配置文件不变，配置版本号也不变。这个值不在档位上（比如手改成 `112` 或字符串）时按 100% 处理，不会当作配置损坏。配置来自更新版本时，本次仍然缩放，但设置里会提示无法保存。

## 终端配色与字体

终端支持 ANSI 16 色、256 色和真彩色。启动 ssh 时设置 `TERM=xterm-256color` 和 `COLORTERM=truecolor`。从 Finder 或开始菜单启动时 TERM 本来是空的，远端会当作不支持颜色的终端，`ls --color=auto` 和 Debian / Ubuntu 默认的彩色提示符都不会开。`TERM` 会随 ssh 传到远端；`COLORTERM` 只在本机进程里，远端 sshd 默认不接收。

设置里的「配色」可以选内置配色，下面的色块是这套配色的 16 种颜色：

| 配色 | 说明 |
| --- | --- |
| 夜幕（默认） | 与界面同色的深色背景，颜色柔和 |
| 深海 | 深蓝背景，颜色饱和 |
| One Dark、Dracula、Tokyo Night、Nord、Solarized Dark | 常见深色配色 |
| 纸白 | 浅色背景，xterm 自动提高过浅文字的对比度 |

每套配色里，`ls` 用来区分文件类型的红、绿、黄、蓝、品红、青六种颜色互不相同，在深色背景上对比度至少 3:1（测试里检查）。

「终端字体」默认用内置的 JetBrains Mono（SIL OFL 1.1，许可证见 [docs/THIRD_PARTY_LICENSES.md](docs/THIRD_PARTY_LICENSES.md)）。也可以选「系统默认」或本机已安装的 SF Mono、Menlo、Cascadia Mono、Consolas、Fira Code、MesloLGS NF；没装的会标「未安装」且不能选。中文按字回退到苹方或微软雅黑。

改配色或字体会立刻作用到所有已打开的标签，终端重新计算行列。选择写在 `config.json` 的 `settings.terminalTheme` 和 `settings.terminalFont`，默认值不写；未知的值按默认处理，不当作配置损坏。

## 拓扑首页

首页是本机 `topology.json` 的网络拓扑图。它和 `config.json` 在同一目录：

- macOS：`~/Library/Application Support/my-terminal/topology.json`
- Windows：`%APPDATA%\my-terminal\topology.json`

仓库里的 [topology.example.json](topology.example.json) 只含占位地址。复制到上面的路径后，点「重新加载」。文件缺失或格式不对时，首页会写出具体原因。原来的 Tailscale 列表和手动添加仍在工具栏右侧的「手动服务器」，再点一次或点「拓扑」标签回到拓扑图。

每个区域一个圆角分组框，按文件顺序从左到右排，放不下就换行，每一行拉伸铺满窗口宽度，窗口大小变化时重新排布。设备是内联 SVG 图标，`type` 取 `server`、`mac`、`windows`、`router`、`nas`、`cloud`，不区分大小写。不写 `type` 时按名称猜测：先转成小写，再按 `-`、`_`、`.`、空格和中英文边界切成词，整词匹配（所以 `machine` 不是 Mac，`twin` 不是 Windows）。中文关键词按包含匹配，例如名称里的「路由」。类别按路由器、NAS、Mac、Windows、云、服务器的顺序，先匹配到的为准。猜不出、空字符串或不认识的取值用通用图标，文件照常加载。猜测可能不准，写上 `type` 即可纠正。没有 `type` 的旧配置也能打开。

图标下面是名称和 `host:port`，不显示用户名。跳板画成带箭头的曲线，同一区域内是实线，跨区域是虚线，多级跳板每一跳一条线。移动设备在图标右上角有标记。配了 `tailscaleAddress` 的设备仍在图标左下角用圆点表示在线、离线或未知。

点击一台设备，或用 Tab 选中后按 Enter 或 Space，总是新开一个标签并切过去。同一台设备可以开多个标签，标题按打开顺序编号，关掉中间的会重新编号。拓扑首页固定在第一个标签，标题是「拓扑」，没有关闭按钮。标签上会显示连接中、已连接、已断开或连接失败。会话标签最多 8 个，首页不算；满了再点设备会提示「最多 8 个标签」，节点带上 `aria-disabled`。

关闭当前标签：macOS 用 Cmd+W，Windows 用 Ctrl+Shift+W 或 Ctrl+F4。裸 Ctrl+W 不拦截，留给 shell。连接中和已连接的标签关闭前会确认。Cmd/Ctrl+1 到 8 跳到第 N 个标签（首页是 1），Cmd/Ctrl+9 跳到最后一个。这些键在窗口捕获阶段处理，同时 xterm 的自定义键处理返回 false，所以不会写进远端。组字、Alt 和表单输入框里不触发。标签后面的「+」（新建）和 Cmd+T（Windows 为 Ctrl+Shift+T）回到拓扑首页。

界面只把设备名交给后端。主机、用户、端口、密钥路径和跳板都由后端按文件拼出来，再调用系统 ssh。跳板机如果写了密钥路径，会生成一份临时 ssh 配置：Unix 上权限是 `0600`；Windows 上用 `%SystemRoot%\System32\icacls.exe` 去掉继承，并尽量只留给当前用户。跳板机配置了密钥路径时会用 `-F`，此时不会读取 `/etc/ssh/ssh_config`（包括 macOS 的 `ssh_config.d`）。用户自己的 `~/.ssh/config` 通过 `Match all` 之后的 `Include ~/.ssh/config` 保留。会话结束或退出应用时删除临时文件。配了 `tailscaleAddress` 的设备会对照 Tailscale 状态显示在线、离线或「未知」；连上去用的仍是 `host`。

同一台设备还可以额外声明 `connections`，和原来的直连或 `jump`（ProxyJump，参数 `-J`）并存。没有这个字段的旧文件行为不变。`jump` 仍是默认方式。每一项是经跳板机在远端执行一条命令，再用这条命令的标准输入输出接通目标机：

```json
"connections": [
  {"name": "经跳板命令", "via": "跳板机", "command": "tailscale nc %h %p"}
]
```

某条中转要连目标机的另一个地址时（例如经 NAS 连目标机的 Tailscale 地址），在这一项里写 `host`，需要时再写 `port`。它们只对这条连接生效，不写时用设备自己的 `host` 和 `port`：

```json
{"name": "经 NAS", "via": "office-nas", "command": "tailscale nc %h %p", "host": "192.0.2.50"}
```

`name` 在同一台设备里不能重复，也不能叫「默认」。`via` 必须是另一台设备，而且那台跳板机自己不能再写 `jump` 或 `connections`。`command` 是在跳板机上执行的命令模板，必须同时包含 `%h` 和 `%p`：`%h` 换成目标主机，`%p` 换成目标端口，`%%` 换成一个百分号。目标主机和端口取这一项的 `host`、`port`，没写就取设备的，ssh 最终连接、核对 known_hosts 和失败提示也都用它们。`host` 只允许字母、数字和 `.` `-` `_`，`port` 范围与设备相同。模板里只允许字母、数字、空格，以及 `.` `_` `/` `:` `=` `@` `+` `-`。分号、管道、引号、重定向、换行、波浪号和其他 `%` 占位符会在读取配置时被拒绝。

这种连接使用 OpenSSH 的 `ProxyCommand`。应用自己先把 `%h` 和 `%p` 换好，再交给 ssh。启动 ssh 进程仍然不经过 shell。跳板机的密钥路径会作为内层 ssh 的 `-i`。认证只用密钥、ssh-agent 或 Tailscale SSH，不支持在跳板机上输入口令。

ssh 以 255 退出时，终端末尾追加一行提示：跳板机出错、目标机出错、中转命令或目标机不可达，或者未知。原来的 ssh 输出仍保留。

设备没有 `connections` 时，点击仍直接打开默认方式。有的时候先弹出菜单：第一项是「默认（直连/ProxyJump）」，后面是每条中转命令的名称。方向键移动，Enter 或 Space 打开，Esc 或点外面关闭。默认方式的标签标题是设备名；选了中转命令则是「设备名 · 连接名」。界面只提交设备名和连接名，不提交主机或命令。菜单里可以检查命令模板，允许的字符与后端相同，真正生效的仍是 `topology.json`。不支持在跳板机上输入口令。
